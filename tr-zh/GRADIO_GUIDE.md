## 快速開始

### 啟動演示

```bash
# 基本啟動
python app.py

# 預初始化
python app.py --config acestep-v15-turbo --init-llm

# 指定埠
python app.py --port 7860
```

### 介面概述

Gradio 介面佈局如下：

1. **設定**（摺疊式手風琴）- 服務配置、DiT/LM 參數、輸出選項
2. **生成標籤頁** - 主工作區，頂部有**生成模式**單選選擇器：
   - Turbo/SFT 模型：Simple、Custom、Remix、Repaint
   - Base 模型：Simple、Custom、Remix、Repaint、Extract、Lego、Complete
3. **結果區域** - 生成的音訊播放、評分、批次導航
4. **訓練標籤頁** - 資料集構建器和 LoRA 訓練

## 服務配置

### 模型選擇

| 設定 | 說明 |
|---------|-------------|
| **檢查點檔案** | 選擇已訓練的模型檢查點（如果可用）|
| **主模型路徑** | 選擇 DiT 模型配置（例如 `acestep-v15-turbo`、`acestep-v15-turbo-shift3`）|
| **裝置** | 處理裝置：`auto`（推薦）、`cuda` 或 `cpu` |

### 5Hz LM 配置

| 設定 | 說明 |
|---------|-------------|
| **5Hz LM 模型路徑** | 選擇語言模型。**可用模型根據 GPU 等級自動過濾** — 例如，6-8GB GPU 僅顯示 0.6B，而 24GB+ GPU 顯示所有尺寸（0.6B、1.7B、4B）。|
| **5Hz LM 後端** | `vllm`（更快，推薦顯示記憶體 ≥8GB 的 NVIDIA GPU）、`pt`（PyTorch，通用回退方案）或 `mlx`（Apple Silicon）。**顯示記憶體 <8GB 的 GPU 限制為 `pt`/`mlx`**，因為 vllm 的 KV 快取佔用過大。|
| **初始化 5Hz LM** | 勾選以在初始化期間載入 LM（thinking 模式必需）。**顯示記憶體 ≤6GB 的 GPU（Tier 1-2）預設不勾選且禁用。**|

> **自適應預設設定**: 所有 LM 設定根據 GPU 顯示記憶體等級自動配置。推薦的 LM 模型、後端和初始化狀態已預設為最佳效能。您可以手動覆蓋，但如果選擇與 GPU 不相容，系統會發出警告。

### 效能選項

| 設定 | 說明 |
|---------|-------------|
| **使用 Flash Attention** | 啟用以加速推理（需要 flash_attn 包）|
| **卸載到 CPU** | 空閒時將模型卸載到 CPU 以節省 GPU 顯示記憶體。**顯示記憶體 <20GB 的 GPU 預設自動啟用。**|
| **將 DiT 卸載到 CPU** | 專門將 DiT 模型卸載到 CPU。**顯示記憶體 <12GB 的 GPU 預設自動啟用。**|
| **INT8 量化** | 使用 INT8 權重量化減少模型顯示記憶體佔用。**顯示記憶體 <20GB 的 GPU 預設自動啟用。**|
| **模型編譯** | 啟用 `torch.compile` 最佳化推理。**所有等級預設啟用**（量化啟用時必需）。|

> **等級感知設定**: 卸載、量化和編譯選項根據 GPU 等級自動設定。詳見 [GPU_COMPATIBILITY.md](GPU_COMPATIBILITY.md) 瞭解完整的等級表。

### LoRA 介面卡

| 設定 | 說明 |
|---------|-------------|
| **LoRA 路徑** | 已訓練的 LoRA 介面卡目錄路徑 |
| **載入 LoRA** | 載入指定的 LoRA 介面卡 |
| **卸載** | 移除當前載入的 LoRA |
| **使用 LoRA** | 啟用/禁用已載入的 LoRA 進行推理 |

> **⚠️ 注意：** 由於 PEFT 和 TorchAO 之間的相容性問題，無法在量化模型上載入 LoRA 介面卡。如果需要使用 LoRA，請在載入介面卡之前將 **INT8 量化** 設定為 **None**。

### 初始化

點選 **初始化服務** 載入模型。狀態框將顯示進度和確認資訊，包括：
- 檢測到的 GPU 等級和顯示記憶體
- 最大允許時長和批次大小（根據是否初始化了 LM 動態調整）
- 任何不相容設定被自動修正的警告

初始化後，**音訊時長** 和 **批次大小** 滑塊會自動更新以反映等級限制。

## 生成模式

生成標籤頁頂部的**生成模式**單選選擇器決定了你的工作流。Turbo 和 SFT 模型提供四種模式；Base 模型額外增加三種。

### Simple 模式

專為快速、基於自然語言的音樂生成設計。

**使用方法：**
1. 在生成模式中選擇 **Simple**
2. 在"歌曲描述"欄位中輸入自然語言描述
3. 如果不想要人聲，可選擇勾選"純音樂"
4. 可選擇首選人聲語言
5. 點選 **建立樣本** 生成 caption、歌詞和後設資料
6. 在展開的部分中檢視生成的內容
7. 點選 **生成音樂** 建立音訊

**示例描述：**
- "一首適合安靜夜晚的柔和孟加拉情歌"
- "歡快的電子舞曲，重低音"
- "憂鬱的獨立民謠，原聲吉他"
- "在煙霧瀰漫的酒吧裡演奏的爵士三重奏"

**隨機樣本：** 點選 🎲 按鈕載入隨機示例描述。

### Custom 模式

完全控制所有生成參數（text2music）。

**使用方法：**
1. 在生成模式中選擇 **Custom**
2. 手動填寫 Caption 和歌詞欄位
3. 可選上傳參考音訊用於風格引導
4. 設定可選後設資料（BPM、調性、時長等）
5. 可選點選 **格式化** 使用 LM 增強您的輸入
6. 根據需要配置高階設定
7. 點選 **生成音樂** 建立音訊

### Remix 模式

保持現有音訊的旋律結構，同時改變風格。

**使用方法：**
1. 在生成模式中選擇 **Remix**
2. 上傳源音訊（要 remix 的歌曲）
3. 編寫描述目標風格的 Caption
4. 可選修改歌詞
5. 調整 **Remix 強度**（0.0-1.0）：越高 = 越接近原始結構
6. 點選 **生成音樂**

**用例：** 建立翻唱版本、風格遷移、生成歌曲變體。

### Repaint 模式

重新生成音訊的特定時間段，保持其餘部分不變。

**使用方法：**
1. 在生成模式中選擇 **Repaint**
2. 上傳源音訊
3. 設定**重繪開始**和**重繪結束**（秒；-1 表示檔案末尾）
4. 編寫描述重繪部分期望內容的 Caption
5. 點選 **生成音樂**

**用例：** 修復有問題的部分、修改某段歌詞、延長歌曲。

### Extract 模式（僅 Base 模型）

從混音音訊中提取/分離特定樂器軌道。

**使用方法：**
1. 在生成模式中選擇 **Extract**
2. 上傳源音訊
3. 從下拉選單中選擇要提取的**軌道名稱**
4. 點選 **生成音樂**

**可用軌道：** vocals、backing_vocals、drums、bass、guitar、keyboard、percussion、strings、synth、fx、brass、woodwinds

### Lego 模式（僅 Base 模型）

為現有音訊新增新的樂器軌道。

**使用方法：**
1. 在生成模式中選擇 **Lego**
2. 上傳源音訊
3. 從下拉選單中選擇要新增的**軌道名稱**
4. 編寫描述軌道特徵的 Caption
5. 點選 **生成音樂**

### Complete 模式（僅 Base 模型）

用指定的樂器完成部分軌道（自動編排）。

**使用方法：**
1. 在生成模式中選擇 **Complete**
2. 上傳源音訊
3. 選擇多個要新增的**軌道名稱**
4. 編寫描述期望風格的 Caption
5. 點選 **生成音樂**

## 輸入參數

### 音訊輸入

| 欄位 | 說明 |
|-------|-------------|
| **參考音訊** | 用於風格/音色引導的可選音訊（Custom 模式下可見） |
| **源音訊** | Remix、Repaint、Extract、Lego、Complete 模式必需 |
| **轉換為程式碼** | 從源音訊提取 5Hz 語義程式碼 |

#### LM 程式碼提示（Custom 模式）

可以在此貼上預計算的音訊語義程式碼來引導生成。使用 **轉錄** 按鈕分析程式碼並提取後設資料。這是一個高階功能，用於在不上傳源音訊的情況下控制旋律結構。

### 音樂描述

期望音樂的文字描述。請具體說明：
- 風格和型別
- 樂器
- 情緒和氛圍
- 節奏感（如果不指定 BPM）

**示例：** "歡快的流行搖滾，電吉他、有力的鼓點和朗朗上口的合成器鉤子"

點選 🎲 載入隨機示例 caption。

### 歌詞

輸入帶結構標籤的歌詞：

```
[Verse 1]
今天走在街上
想著你曾說過的話

[Chorus]
我在前進，我很堅強
這就是我屬於的地方

[Verse 2]
...
```

**純音樂核取方塊：** 勾選此項以生成純音樂，無論歌詞內容如何。

**人聲語言：** 選擇人聲語言。對於自動檢測或純音樂，使用"unknown"。

**格式化按鈕：** 點選使用 5Hz LM 增強 caption 和歌詞。

### 可選參數

| 參數 | 預設值 | 說明 |
|-----------|---------|-------------|
| **BPM** | 自動 | 每分鐘節拍數（30-300）|
| **調性** | 自動 | 音樂調性（例如"C Major"、"Am"、"F# minor"）|
| **拍號** | 自動 | 拍號：2（2/4）、3（3/4）、4（4/4）、6（6/8）|
| **音訊時長** | 自動/-1 | 目標長度（秒）（10-600）。-1 為自動 |
| **批次大小** | 2 | 要生成的音訊變體數量（1-8）|

## 高階設定

### DiT 參數

| 參數 | 預設值 | 說明 |
|-----------|---------|-------------|
| **推理步數** | 8 | 去噪步數。Turbo：1-20，Base：1-200 |
| **引導比例** | 7.0 | CFG 強度（僅 base 模型）。越高 = 越遵循提示 |
| **種子** | -1 | 隨機種子。批次使用逗號分隔的值 |
| **隨機種子** | ✓ | 勾選時生成隨機種子 |
| **音訊格式** | mp3 | 輸出格式：mp3、flac |
| **偏移** | 3.0 | 時間步偏移因子（1.0-5.0）。turbo 推薦 3.0 |
| **推理方法** | ode | ode（Euler，更快）或 sde（隨機）|
| **自定義時間步** | - | 覆蓋時間步（例如"0.97,0.76,0.615,0.5,0.395,0.28,0.18,0.085,0"）|

### 僅 Base 模型參數

| 參數 | 預設值 | 說明 |
|-----------|---------|-------------|
| **使用 ADG** | ✗ | 啟用自適應雙引導以獲得更好的品質 |
| **CFG 區間開始** | 0.0 | 何時開始應用 CFG（0.0-1.0）|
| **CFG 區間結束** | 1.0 | 何時停止應用 CFG（0.0-1.0）|

### LM 參數

| 參數 | 預設值 | 說明 |
|-----------|---------|-------------|
| **LM 溫度** | 0.85 | 取樣溫度（0.0-2.0）。越高 = 越有創意 |
| **LM CFG 比例** | 2.0 | LM 引導強度（1.0-3.0）|
| **LM Top-K** | 0 | Top-K 取樣。0 禁用 |
| **LM Top-P** | 0.9 | 核取樣（0.0-1.0）|
| **LM 負面提示** | "NO USER INPUT" | CFG 的負面提示 |

### CoT（思維鏈）選項

| 選項 | 預設值 | 說明 |
|--------|---------|-------------|
| **CoT Metas** | ✓ | 透過 LM 推理生成後設資料 |
| **CoT Language** | ✓ | 透過 LM 檢測人聲語言 |
| **約束解碼除錯** | ✗ | 啟用除錯日誌 |

### 生成選項

| 選項 | 預設值 | 說明 |
|--------|---------|-------------|
| **LM 程式碼強度** | 1.0 | LM 程式碼對生成的影響程度（0.0-1.0）|
| **自動評分** | ✗ | 自動計算品質分數 |
| **自動 LRC** | ✗ | 自動生成歌詞時間戳 |
| **LM 批處理塊大小** | 8 | 每個 LM 批次的最大專案數（GPU 記憶體）|

### 主要生成控制

| 控制 | 說明 |
|---------|-------------|
| **Think** | 啟用 5Hz LM 進行程式碼生成和後設資料 |
| **ParallelThinking** | 啟用並行 LM 批處理 |
| **CaptionRewrite** | 讓 LM 增強輸入 caption |
| **AutoGen** | 完成後自動開始下一批次 |

## 結果區域

### 生成的音訊

根據批次大小最多顯示 8 個音訊樣本。每個樣本包括：

- **音訊播放器** - 播放、暫停和下載生成的音訊
- **傳送到源** - 將此音訊傳送到源音訊輸入以進行進一步處理
- **儲存** - 將音訊和後設資料儲存到 JSON 檔案
- **評分** - 計算基於困惑度的品質分數
- **LRC** - 生成歌詞時間戳（LRC 格式）

### 詳情摺疊面板

點選"評分 & LRC & LM 程式碼"展開並檢視：
- **LM 程式碼** - 此樣本的 5Hz 語義程式碼
- **品質分數** - 基於困惑度的品質指標
- **歌詞時間戳** - LRC 格式的時間資料

### 批次導航

| 控制 | 說明 |
|---------|-------------|
| **◀ 上一批** | 檢視上一批 |
| **批次指示器** | 顯示當前批次位置（例如"批次 1 / 3"）|
| **下一批狀態** | 顯示後台生成進度 |
| **下一批 ▶** | 檢視下一批（如果 AutoGen 開啟則觸發生成）|

### 恢復參數

點選 **應用這些設定到 UI** 將當前批次的所有生成參數恢復到輸入欄位。適用於迭代最佳化好的結果。

### 批次結果

"批次結果和生成詳情"摺疊面板包含：
- **所有生成的檔案** - 下載所有批次的所有檔案
- **生成詳情** - 關於生成過程的詳細資訊

## LoRA 訓練

LoRA 訓練選項卡提供建立自定義 LoRA 介面卡的工具。

> 📖 **完整的分步教學**（資料準備、標註、預處理、訓練和匯出），請參閱 [LoRA 訓練教學](./LoRA_Training_Tutorial.md)。

### 資料集構建器選項卡

#### 步驟 1：載入或掃描

**選項 A：載入現有資料集**
1. 輸入之前儲存的資料集 JSON 路徑
2. 點選 **載入**

**選項 B：掃描新目錄**
1. 輸入音訊資料夾路徑
2. 點選 **掃描** 查詢音訊檔案（wav、mp3、flac、ogg、opus）

#### 步驟 2：配置資料集

| 設定 | 說明 |
|---------|-------------|
| **資料集名稱** | 您的資料集名稱 |
| **全部純音樂** | 如果所有曲目都沒有人聲，請勾選 |
| **自定義啟用標籤** | 啟用此 LoRA 風格的唯一標籤 |
| **標籤位置** | 放置標籤的位置：前置、追加或替換 caption |

#### 步驟 3：自動標註

點選 **自動標註全部** 為所有音訊檔案生成後設資料：
- Caption（音樂描述）
- BPM
- 調性
- 拍號

**跳過 Metas** 選項將跳過 LLM 標註並使用 N/A 值。

#### 步驟 4：預覽和編輯

使用滑塊選擇樣本並手動編輯：
- Caption
- 歌詞
- BPM、調性、拍號
- 語言
- 純音樂標誌

點選 **儲存更改** 更新樣本。

#### 步驟 5：儲存資料集

輸入儲存路徑並點選 **儲存資料集** 匯出為 JSON。

#### 步驟 6：預處理

將資料集轉換為預計算張量以加快訓練：
1. 可選載入現有資料集 JSON
2. 設定張量輸出目錄
3. 點選 **預處理**

這會將音訊編碼為 VAE 潛變數，將文字編碼為嵌入，並執行條件編碼器。

### 訓練 LoRA 選項卡

#### 資料集選擇

輸入預處理張量目錄路徑並點選 **載入資料集**。

#### LoRA 設定

| 設定 | 預設值 | 說明 |
|---------|---------|-------------|
| **LoRA 秩 (r)** | 64 | LoRA 容量。越高 = 容量越大，記憶體越多 |
| **LoRA Alpha** | 128 | 縮放因子（通常是秩的 2 倍）|
| **LoRA Dropout** | 0.1 | 用於正則化的 dropout 率 |

#### 訓練參數

| 設定 | 預設值 | 說明 |
|---------|---------|-------------|
| **學習率** | 1e-4 | 最佳化學習率 |
| **最大 Epochs** | 500 | 最大訓練 epochs |
| **批次大小** | 1 | 訓練批次大小 |
| **梯度累積** | 1 | 有效批次 = batch_size × accumulation |
| **每 N Epochs 儲存** | 200 | 檢查點儲存頻率 |
| **偏移** | 3.0 | turbo 模型的時間步偏移 |
| **種子** | 42 | 用於可重複性的隨機種子 |

#### 訓練控制

- **開始訓練** - 開始訓練過程
- **停止訓練** - 中斷訓練
- **訓練進度** - 顯示當前 epoch 和損失
- **訓練日誌** - 詳細訓練輸出
- **訓練損失圖** - 視覺化損失曲線

#### 匯出 LoRA

訓練後，匯出最終介面卡：
1. 輸入匯出路徑
2. 點選 **匯出 LoRA**

## 技巧與最佳實踐

### 獲得最佳品質

1. **使用 thinking 模式** - 保持"Think"核取方塊啟用以獲得 LM 增強的生成
2. **具體描述 caption** - 包含風格、樂器、情緒和風格細節
3. **讓 LM 檢測後設資料** - 將 BPM/調性/時長留空以自動檢測
4. **使用批次生成** - 生成 2-4 個變體並選擇最好的

### 加快生成速度

1. **使用 turbo 模型** - 選擇 `acestep-v15-turbo` 或 `acestep-v15-turbo-shift3`
2. **保持推理步數為 8** - 這是 turbo 的最佳預設值
3. **減少批次大小** - 如果需要快速結果，降低批次大小
4. **禁用 AutoGen** - 手動控制批次生成

### 獲得一致結果

1. **設定特定種子** - 取消勾選"隨機種子"並輸入種子值
2. **儲存好的結果** - 使用"儲存"匯出參數以便重現
3. **使用"應用這些設定"** - 從好的批次恢復參數

### 長格式音樂

1. **設定明確的時長** - 以秒為單位指定時長
2. **使用 repaint 任務** - 初始生成後修復有問題的部分
3. **鏈式生成** - 使用"傳送到源"在之前的結果上構建

### 風格一致性

1. **訓練 LoRA** - 為您的風格建立自定義介面卡
2. **使用參考音訊** - 在音訊上傳中上傳風格參考
3. **使用一致的 caption** - 保持相似的描述性語言

### 故障排除

**沒有生成音訊：**
- 檢查模型是否已初始化（綠色狀態訊息）
- 如果使用 thinking 模式，確保 5Hz LM 已初始化
- 檢查狀態輸出中的錯誤訊息

**結果品質差：**
- 增加推理步數（對於 base 模型）
- 調整引導比例
- 嘗試不同的種子
- 使 caption 更具體

**顯示記憶體不足 (OOM)：**
- 系統包含自動顯示記憶體管理（顯示記憶體守衛、自適應 VAE 解碼、自動批次減小）。如果仍然 OOM：
- 手動減少批次大小
- 啟用 CPU 卸載（顯示記憶體 <20GB 應已自動啟用）
- 啟用 INT8 量化（顯示記憶體 <20GB 應已自動啟用）
- 減少 LM 批處理塊大小
- 詳見 [GPU_COMPATIBILITY.md](GPU_COMPATIBILITY.md) 瞭解各等級推薦設定

**LM 不工作：**
- 確保初始化期間勾選了"初始化 5Hz LM"（顯示記憶體 ≤6GB 的 GPU 預設禁用）
- 檢查是否選擇了有效的 LM 模型路徑（僅顯示與等級相容的模型）
- 驗證 vllm 或 PyTorch 後端可用（顯示記憶體 <8GB 限制使用 vllm）
- 如果 LM 核取方塊灰色不可用，說明您的 GPU 等級不支援 LM — 請使用純 DiT 模式
